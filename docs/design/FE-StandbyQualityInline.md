# 队列页质量内联改造设计（FE-StandbyQualityInline）

> 后续变更（2026-09）：**低质量标记功能（qualityFlags / 慢·失败·不稳·脏标签 / row-flag 色条高亮）已整体移除**——代理质量由后端心跳机制自动管理（失败计数→退避补测→拉黑淘汰），前端不做主动检查。本文其余部分（行下质量带、逐代理序列、共享时间窗口等）仍为当前实现依据。
>
> 后续变更（2026-09）：§4.3 / §5.1 列的 standby 行字段里，`source_group` 与 `protocol` 已不再下发——`move_proxy` 不保留来源组（值恒为 None），协议由前端从代理地址文本里的 scheme 得到；该两节为当时的改动记录，字段以 `docs/architecture.md` 与 `src/framework/web/api.py` 为准。
>
> 目标：代理信息与质量在**同一个页面滚动可见**，取消悬浮面板，不必逐行点进去看。
>
> 已对齐约束：
> 1. 「一页可见」= 同页滚动可见全部（不要求压进一屏，图表可以放大看清楚）；
> 2. 质量维度含延时趋势、流量、纯净度、带宽测速，但**不要求一次全部显示**；
> 3. 带宽测速与纯净度**均不自动采集**，保留手动触发、结果就地展示；
> 4. **展示形态采用方案 B（行下质量带）**——以本文为准，下表 3.1 记录了否决方案的取舍理由。

## 1. 现状与问题

队列页每行只有 `地址 / 延迟 / 连续失败 / 缓存的纯净度 tag`；延时趋势、流量速率、测速结果全在悬浮面板（`ProxyTooltip.vue` + `useProxyTooltip.ts`），必须悬停才可见，一次只能看一个代理，无法比较。

数据侧的关键事实：**这些数据后端都已经有了**，缺的只是下发通道。

| 数据 | 现状 | 来源 | 缺口 |
|---|---|---|---|
| 延时采样 | 仅悬浮面板按需查 | `StandbyQueueUseCase._per_proxy_latency_history`，探测**成功**时记点 | 失败不记点 → 曲线拉直，看不出掉线、算不出成功率 |
| 流量采样 | 仅悬浮面板按需查 | `PproxyServer._per_proxy_traffic_history`，独立采样循环固定 2s 采累计字节（不随心跳放宽，锁定时流量照常采） | 无 |
| 归属地 | 队列页没有 | `.cache.db` 的 `ip_geo_cache`（代理组页在用） | 队列页未下发 |
| 协议 / 来源 / 入队时长 | 队列页没有 | 组内条目字段（代理组页在用） | 队列页未下发 |
| 纯净度 | 有（`ippure.toml` cache_ttl，默认 30 天） | `_purity_cached()` | 未检查过的行是空的 |
| 带宽测速 | 仅悬浮面板手动 | `vendor/pspeed` `probe_one`，单代理约 10s | 结果无处落地展示 |

## 2. 硬约束

1. **数据量**：心跳 2s/轮、样本按全局 `metrics_window=1800s` 留存 → 单代理单序列约 900 点；30 块 × 3 序列 ≈ 上万点，塞不进 2s 轮询。必须走「增量游标 + 前端累积 + 渲染时降采样 + 队列页按 `standby_chart_window=60s` 裁剪显示范围」，与仪表盘历史（`/api/status/history?since=`）同构。
2. **每块一个 ECharts 实例是已知反模式**：实例自带完整 option 解析、组件体系、事件监听、ResizeObserver；30 块就是 60 个实例，DOM 与内存开销不可接受。行内图用轻量 SVG 自绘（30 块 × 2 条 × 60 点 = 3600 坐标，重算微秒级），ECharts 保留给仪表盘大图。
3. **失败期必须画成断线**：现在探测失败不记点，序列时间戳不连续。行内图**必须按时间戳映射 x 轴**（现有 tooltip 按下标等距铺开，会把掉线抹平），缺口断线。
4. **外部重操作不能自动全量跑**：CF 测速单代理约 10s（30 个串行约 5 分钟且吃带宽）；纯净度检查源（AbuseIPDB 等）有日限额，现有代码明确「不做批量轮询」。
5. **表格交互不能退化**：框选/多选、右键菜单、锁定灰显、顺序冻结、固定/锁定语义全保留。

## 3. 方案决策

### 3.1 形态取舍

| 方案 | 结论 | 理由 |
|---|---|---|
| **B 行下质量带** | **采用** | 图可以做到 320×44 级别，趋势与抖动看得清；横向不受列宽挤压；信息完整度最高 |
| A 行内紧凑列（44px 单行） | 否决 | sparkline 只能 52×16，趋势看不出；1440 视口下列一多就挤 |
| C 卡片网格 | 否决 | 一屏只 4-6 张、30 条要翻几屏，与「滚动可见全部」相悖，还要重写框选/多选/右键 |

B 的固有代价（必须主动缓解，见 3.3 / 3.4）：

- **行高翻倍**：30 块 ≈ 3.5 屏 → 用「折叠」把质量带一键收起，折叠态回到 1.7 屏，等于两套密度共用一套数据与组件。
- **横向比较变弱**：曲线不再列对齐排布 → 用①带内固定位置放数值摘要（延迟/失败/成功率/累计流量，一列排开仍可纵向扫）②表头点列排序 ③低质量高亮 来补偿。

### 3.2 块结构（关键工程决策）

**每个代理 = 一个 `<tr>`，行内一个 `<td colspan="5">` 承载「摘要行 + 质量带」两段**，而不是两个 `<tr>`。

```html
<tr :data-idx="i" :data-proxy="p.proxy" :class="{ selected, 'row-locked', 'row-dimmed' }">
  <td colspan="5">
    <div class="prow">摘要行（grid，列与表头对齐）</div>
    <div class="pstrip" v-show="expanded">质量带（自由 grid 布局）</div>
  </td>
</tr>
```

理由（这是本方案成本低的核心）：

- `useRowSelection` 用 `closest('tbody tr')` 取 `dataset.idx`、`indexAtY` 遍历 `tbody.children` 求块索引、`tr.selected` 高亮、右键 `closest('tbody tr')` —— **单 `tr` 结构下这些全部原样工作**，框选/多选/冻结逻辑零改造。
- 若改成「两个 `tr` 一组」，则选中/索引/高亮/右键/冻结/hover 判定全部要引入"块语义"并逐一改写，且 e2e 选择器全废——收益相同、风险高得多。
- `<td colspan>` 内部用 grid 自由布局，质量带不受列宽约束（这正是 B 要的）。

代价与对策：摘要行的列不再由表格布局算法决定，而要与表头对齐 → 表格设 `table-layout: fixed` 并在 `thead th:nth-child(n)` 上定义列宽（一组 `--sb-col-*` 变量），摘要行 grid 直接引用同一组变量并采用与 `th` 相同的单元格内边距，列边界单一来源、不会漂移（实施时用 `thead th` 宽度取代了原设计的 `colgroup`，见 §9）。

### 3.3 块内布局

```
摘要行 56px（列与表头一致）
┌────┬──────────────────────────────┬────────┬─────────┬──────────┐
│ #  │ 地址（等宽字体）              │ 延迟   │ 连续失败 │ 操作      │
│    │ 美国 · 数据中心 · http ·      │0.181s  │    0     │纯净 固定 锁定│
│    │ 来源 default-http · 入队 42m  │        │          │          │
└────┴──────────────────────────────┴────────┴─────────┴──────────┘
质量带 60px（td colspan 内自由 grid，可折叠）
┌────────────────────────┬────────────────────┬──────────────────────┐
│ 延时趋势  320×44        │ 流量速率  260×44    │ 指标 chips 200px      │
│ （按时间戳映射，断线）   │ （累计差分得速率）   │ 成功率 · 累计流量 ·   │
│                        │                    │ 纯净度 · 测速结果      │
└────────────────────────┴────────────────────┴──────────────────────┘
```

- 表格总列宽与现状一致（`# | 代理 | 延迟 | 连续失败 | 操作`），**表头不用改**，代理列加第二行小字承载归属地/协议/来源/入队时长。
- 块高：摘要 56 + 质量带 60 = 116px（质量带默认展开；收起态 56px，用面板右上角「收起图表」切换）。
- 质量带内四块固定渲染（见 3.5），没有数据的块显示占位文案。
- 两张图左侧各留一列标出该图的数据值区间（上 = 最大、下 = 最小，与坐标映射同源 `sparkDomain`）：
  迷你图没有坐标轴，不标就读不出量级（"1.2s 还是 0.2s"）；该列**只要给了格式化器就占位**
  （哪怕本行暂时没有可绘制点），否则绘图区会在行与行之间、以及同一行的延时图与流量图之间错位。
- 锁定行置顶、`已锁定` badge、`row-dimmed` 灰显（作用于整个 td，即整块灰显）全部保留。

### 3.4 低质量高亮（补偿横向比较弱）

按可配置阈值给整块加左缘色条 + 淡色底，让"一页可见"直接指向问题代理：

- 连续失败 ≥ 1；或当前延迟 > 1s；或窗口内探测成功率 < 80%（窗口 = `standby_chart_window`，队列页显示窗口，下同）；或纯净度 ≥ 50。
- 规则集中在一个纯函数 `qualityFlags(p, series, purity)` 里（Vitest 直测），阈值改配置即生效；常开、无开关。

### 3.5 信息呈现（最终：全部常显，只留密度开关）

> 用户复核后推翻了本节的原始方案（原为「逐项指标开关 + 折叠 + 高亮开关」）：
> **不要逐项显示开关，四项指标直接常显**，低质量高亮也常开；**只保留「收起/展开图表」**。

- 质量带四块（延时趋势 / 流量速率 / 纯净度 / 测速结果）**始终渲染**；没有数据的块显示占位
  （`暂无采样` / `纯净度未检查` / `未测速`），不留空也不靠开关藏起来。
- 低质量标记（失败 / 慢 / 不稳 / 脏）**常开**，阈值仍集中在 `utils/quality.ts` 便于按需调整。
- 面板顶部只剩「收起图表 / 展开图表」一个密度开关（收起回到单行、便于纵览全队列，跨会话记住），
  逐项开关与高亮开关已删除（`useStandbyMetrics` 原设计已整体删除，展开态用组件内一个 ref + localStorage 表达）。
- 未采集的行显示占位（`未测速` / `未检查`）而不是留空——否则"一页可见"在没点过的行上永远空白。
- **建议补充（待确认）**：顶部加「批量测速 / 批量查纯净度」，按当前可见行串行排队、逐行填入结果。仍然不自动、不后台轮询，但一次点击即可把整页质量补齐。

## 4. 数据契约

### 4.1 `GET /api/standby/series?since=<ts>`

增量返回队列（含锁定代理）的逐代理序列，只含 `ts > since` 的点：

```json
{
  "cursor": 1760000000.0,
  "window": 60,
  "series": {
    "1.2.3.4:8080": {
      "lat":  [[1760000000.0, 0.181], [1760000002.0, null]],
      "up":   [[1760000000.0, 1024]],
      "down": [[1760000000.0, 8192]]
    }
  }
}
```

- `window` = 队列页图表的显示窗口（秒，= `standby_chart_window`，只服务队列页行内图，不参与留存）：前端本地缓冲据此裁剪（见 §9.8），不在前端硬编码。
- `lat` 的 `null` = 该轮探测失败（后端需补记，见 5.1）。
- 首次不带 `since` 返回窗口内全量；前端累积并按窗口裁剪；代理离队后序列自然消失，前端按现存块裁剪缓冲。
- 节拍 2s，增量每轮约 90 个数字量级。

### 4.2 `GET /api/standby/geo`

返回 `{bind: {country, country_code, province, city}}`；复用 `_group_detail` 的三步编排（`query_cache` 主线程 → `locate` executor → `save_cache` 主线程），缓存未命中才定位。
节拍 5 分钟（归属以月计变化）。不放进 `/api/status`：避免 2s 热路径做 SQLite 读并膨胀 payload。

### 4.3 `/api/status` 的 standby 行新增字段

`protocol`（由 scheme 派生）、`source_group`、`joined_at`（前端算入队时长）。

## 7. 风险与取舍

| 风险 | 缓解 |
|---|---|
| 块变高后 30 条要滚 3.5 屏 | 「收起图表」一键回到单行密度（默认展开，跨会话记住）；低质量高亮 + 原因标签把注意力先钉到问题代理 |
| 横向比较不如列对齐 | 带内固定位置数值摘要 + 点列排序 + 低质量高亮 |
| `table-layout: fixed` + 内层 grid 的列对齐靠同一组变量维持 | 列宽变量单一来源（`--col-*`），表头 `colgroup` 与摘要行 grid 都引用它 |
| 30 块 × 2 sparkline × 60 点的重绘开销 | 纯 SVG + computed，禁用 ECharts；实测目标 2s 节拍下无掉帧 |
| 手动模式下新页面质量列全空 | 未采集显示占位文案 + 建议的批量触发按钮 |

## 8. 遗留问题（不在本次范围，需另行决定）

1. 锁定期间右键菜单未受限：灰显行仍可弹菜单并执行移出/拉黑，且会设置选中态，与「灰显行不可交互」矛盾，还可能让顺序冻结持续。
2. 对锁定代理拉黑/移出会静默解锁：`/api/blacklist`、`/api/proxy/move`、`/api/proxy/remove` 均无锁定守卫，上游会从"单一代理"瞬间回落到整个队列且无提示。
3. 文档漂移：`docs/architecture.md` 队列容量一处写 10、配置表写 30（实际 30）；连续失败阈值两处写 2/3、配置表写 5/10（实际 5/10）。

## 9. 实施记录（与前述设计的差异）

1. **列宽用 `thead th:nth-child(n)` 而非 `colgroup`**：`table-layout: fixed` 下首行（表头）单元格宽度即列宽，`col` 元素是多余的一层；列宽变量仍单一来源（`--sb-col-*`）。
2. **操作列增加「测速」按钮**：原设计只把测速留给右键菜单与质量带结果，取消悬浮面板后手动触发的入口不够显眼；现在与「纯净度」并列（两者都是手动触发的单代理探针），质量带的测速区块只展示结果。
3. **逐项显示开关与高亮开关已按用户复核意见删除**（初版实现过指标开关 / 折叠 / 高亮开关）：四项指标常显、高亮常开，只保留「收起/展开图表」一个密度开关；`useStandbyMetrics` 整体删除，展开态改由页面内一个 ref + localStorage 表达。
4. **顺序冻结保留 hover**：原设计写"收缩为选中/拖拽"，实施时改为保留（`hoveredProxy` 只负责冻结位置，值照常轮询更新）。行高翻倍后"读一行图表时行跑位"的影响比原来更明显，这条比设计时的判断更重要。
5. **延时趋势用对数 y 轴**：与仪表盘延迟趋势图一致（跨数量级时线性轴会把差异压平），非线性自适应。
6. **不下发 `source_group`**：`move_proxy` 不保留该字段，队列行的值恒为空 → 发送死字段不如不发；摘要行展示协议/归属地/入队时长（归属地来自 `/api/standby/geo`）。
7. **失败采样覆盖 retry_probe**：心跳与退避补测的每次探测都记点（成功记延迟、失败记 `null`），保证"探测过就有点"，缺口只代表"没探测"。
8. **共享时间窗口**（初版按各自点集归一化，后修正）：`sparkSegments` 的 x 轴窗口由页面统一下发（`seriesTimeWindow`：起 = 全行最早采样点，止 = 现在），全部行与同一行的两条曲线共用——各自归一化时，刚入队只有两点的行与跑了半小时的行长得一样、采样已停止的行也贴到右边缘装成最新；同时 `/api/standby/series` 随响应下发 `window`，前端本地缓冲裁剪不再硬编码窗口值。
9. **孤立单点也要可见**：单点段写两遍同一坐标——只有一个点的 `<polyline>` 不产生可描边子路径，浏览器什么都不画（实测），成双写后零长度子路径的圆头端帽才渲染出那个点。
10. **降采样每桶取桶尾，不取均值**：`downsample` 把序列等距压到 60 点上限，取桶内**最后一点**而非均值——均值会把失败点（`null`）洗成平滑曲线、也会削平尖峰。代价是桶尾恰好为 `null`（探测失败 / 零速率）时，桶内的成功点会被一并吞掉，断线可能被画成一整桶（或反之低估）；这是渲染精度与信息保真的取舍，不是 bug（行内图只有一个像素级宽度可用，重新采样粗粒度无法两全）。当前窗口 60s / 采样 2s = 30 点，低于 60 上限，降采样实际不触发；窗口调大（如 1800s）时该规则才生效。
11. **行内流量图的非正速率不绘制**：`toRates` 把 ≤ 0 的速率置 `null`（既不绘制也不参与 y 值域）——零流量画成平线时，全零会让值域退化、线落在图表中间，看着像"有数据"（且绿色下行后画会盖住上行），也会把真正的尖峰压平；与仪表盘流量图（对数轴上的 0 置 null）同一规则。累计值仍以「累计 ↑x ↓y」的文字下发，故"窗口内没有速率"与"没有采样"能区分开。
